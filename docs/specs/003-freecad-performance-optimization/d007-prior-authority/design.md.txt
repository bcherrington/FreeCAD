## High-Level Design

### System Architecture

Keep archive I/O in App/Base and display work in Gui. Implemented source paths
are buffered property-file copy, element-map token parsing, direct bitmap
conversion, deferred full-resolution image-plane loading and pending tree status
updates. This package reconciles those paths and their remaining acceptance.
The MoE review found source/spec conflicts in image extent safety, calibrated
plane sizing and tree receiver lifetime. Presence of a fast path is not verified
acceptance of its safety or compatibility. T012–T018 own the source corrections
and regression cases; their validation evidence remains pending.
Compact rail geometry belongs to package 002; Sketcher diagnosis history remains
in archived package 000.

### Components and Changes

`src/App/PropertyFile.cpp`: bounded binary copy and read/write/close checks.
`src/Base/Reader.cpp`: registered archive-entry restore dispatch.
`src/App/ElementMap.cpp`: string_view dot tokenizer and numeric token conversion
instead of temporary split vectors; bounded numeric compatibility remains
T015/T016. `src/Gui/BitmapFactory.cpp`: direct 32-bit conversion plus Qt fallback.
`src/Gui/ViewProviderImagePlane.cpp`: pending full-resolution texture lifecycle.
`src/Gui/Tree.cpp`/`Tree.h`: pending restore status scheduling and receiver-owned
application subscriptions. T014 qualifies widget teardown. T017 keeps the owned
status timer scheduled during suppression so direct restore/import can resume
after guards exit, while retaining immediate application finish-open flushing.
Empty restored documents also receive an observer-attachment completion pass.

### Data Models And Flow

Archive entry → Base::Reader → PropertyFileIncluded::RestoreDocFile → temporary
file → read-only permissions and property notification. Image properties defer
while restoring; visible planes load on finishRestoring and hidden planes on
show in the inspected implementation. Required behavior is to keep original
source bytes and independently calibrated plane dimensions unchanged. The
inspected setPlaneSize path conflicts with that requirement after the restoring
flag clears; T013 must separate texture materialization from calibration updates.
No document format, cache schema or public API migration is intended.

## Low-Level Design

### Algorithms And Interfaces

Property restore uses bounded read/gcount/write loops, preserves the existing
non-writable-file early return and brackets changes with aboutToSetValue and
hasSetValue. Base::XMLReader::readFiles dispatches registered ZIP entries.
ElementMap scans dot-separated tokens without allocating a vector per name.
Bitmap conversion handles RGB32, ARGB32, RGBA8888 and RGBX8888 directly, flips
vertically, produces RGBA and finishes SoSFImage editing. Other formats,
including premultiplied alpha, use Qt conversion to RGBA8888 plus a vertical
flip. Do not claim a direct premultiplied scanline path.

ImageFile/XSize/YSize restore updates mark pendingFullResTexture; finishRestoring
loads visible planes and show loads pending hidden planes. Reduced-resolution
placeholders are not implemented. Tree restore batches status scheduling only;
_slotDeleteObject still preserves per-object focus, selection, children and map
side effects. Any bulk-delete bypass needs a separate measured proposal.

### Element-Map Numeric Restoration Policy

T015 preserves the values produced by the five pre-optimization strtol call sites
at `8dc855b1948^`. The private ElementMapRestore.h implementation reads bounded
string_views, uses checked unsigned magnitude and constructs LONG_MIN without
signed negation overflow. It allocates no conversion buffer and exposes neither
end pointers nor errno. The public API and archive writer/format are unchanged.

| Input / field | Accepted or rejected behavior |
| --- | --- |
| Radix | Child SIDs remain decimal; mapped prefix/index/postfix/SID fields remain hexadecimal, including the legacy accidental decimal child-SID format |
| Leading whitespace/sign | C whitespace classification through unsigned char, then one optional plus/minus; normal archive stream extraction still separates whitespace before dot-tokenization |
| Hex prefix | Optional 0x/0X in base16; explicit decimal base does not switch radix |
| Empty, sign-only, no digits | Value zero, matching legacy conversion; each caller applies its existing zero/ID/table policy |
| Invalid suffix or NUL | Longest valid numeric prefix; bounded view may be non-terminated. This is intentional legacy tolerance, not strict full-token validation |
| Long limits and overflow | LONG_MIN/LONG_MAX accepted exactly; out-of-range magnitudes saturate to the corresponding limit, never wrap |
| Table/SID context | Invalid name table indices reject; invalid postfix indices warn/omit; missing SIDs retain existing warning/ignore behavior. Saturation cannot wrap into a valid table/ID alias |
| Mapped element index | Existing IndexedName nonnegative-int domain is enforced before narrowing: 0 through INT_MAX accepted, other values raise Base::RuntimeError. Zero still formats without a numeric suffix |
| Metadata counts/ranges | Negative counts, nonpositive MapCount, and child interval/cumulative-size arithmetic outside the existing representable domain reject before allocation/arithmetic |
| Prefix ownership | Compact colon names before temporary prefix-table storage dies; this fixes the raw-data lifetime at mapped index zero and adds no copy for already-owned positive-index names |

Rejecting structurally invalid metadata and indices formalizes existing type
preconditions; it does not change valid writer output. General archive allocation
budgets, locale-specific non-ASCII numeric extensions, malformed-file document
recovery and Windows/LLP64 qualification are not established here. T016 and T005
qualify writer/alias/child-map and dependent CAD identity and aggregate parser acceptance
locally. T010 retains exact-final/platform applicability.

### Image Qualification Reference

T003 compares canonical RGBA8 against an independent QColor/pixelColor scalar
reference derived from the historical conversion approach. The old raw
sizeInBytes-based component inference is not an oracle for padded, alpha-only
or newer floating-point formats. Preserve source color/alpha semantics rather
than reproducing its unsupported layouts. Direct byte fixtures remain exact;
normalized premultiplied/high-depth scalar comparison permits at most one RGBA8
level for quantization. Real production SoQtOffscreenRenderer image-plane frames
must match the scalar luminance/LA/RGB/RGBA reference within two RGB levels per
pixel, with source-over color at texel centers within three levels. Orientation,
transparent-background blending and world-space scale/placement have independent
analytic assertions; bounding rectangles are exact with zero MSAA. These rules
are set before executing the render matrix. Qualify the native X11/xcb framebuffer
profile required by T019 and record supplementary Qt offscreen results separately.
Framebuffer correctness is distinct from T020's interactive native-view
first-correct-frame timing and T010's platform coverage.

### Error Handling And Compatibility

Preserve binary bytes, entry boundaries, destination permissions and observable
filesystem failures. Verify image format fallback, alpha and texture ownership
rather than extrapolating from four conversion tests. Reopen saved documents,
exercise hidden/visible image transitions and preserve tree/observer behavior.
Do not add production tracing or broader caching without separately reviewed
invalidation and diagnostic contracts.

### MoE Safety And Compatibility Contracts

- **Image extents (F001):** before narrowing dimensions into Coin types, validate
  non-null image, positive representable extents and checked destination/offset
  sizes. T012's QImage-to-Coin conversion accepts positive extents up to
  `std::numeric_limits<short>::max()` (32767 here), with RGBA bytes bounded by
  `qsizetype::max()` using division before multiplication. It clears the output
  to `(0,0)`, zero components and no pixels for null/unsupported input or failed
  fallback format conversion. Direct row offsets use `std::size_t`; narrowing
  follows validation and Coin's four-byte allocation alignment cannot overflow.
  The void API is preserved. Allocation exceptions from Coin remain exceptions;
  this is not an out-of-memory recovery policy. D001/D003 identify backend/build;
  T012 covers both orientations of 32767/32768/65537 slender images and valid
  edge pixels; broader fidelity/calibration qualification remains T003/T006.
- **Calibration (F002):** T013 uses an explicit private image-size policy:
  direct new/replaced image assignment initializes DPI-derived physical sizes;
  pending materialization preserves stored XSize/YSize after transient flags
  clear, while still refreshing image DPI metadata and original texture data.
  Both GUI restoring and App ObjImporting defer ImageFile/XSize/YSize loads.
  Placement and calibrated Coin quad coordinates remain unchanged. The existing
  Gui::Document completion ordering is retained; the provider owns this policy.
  Real offscreen App/Gui archive/copy/import regressions qualify the local fix;
  T003 qualifies local image/render fidelity; T006 qualifies the expanded lifecycle.
  Ordinary show defers while GUI restoring or App ObjImporting without consuming
  the pending request. Object finishRestoring is the explicit payload-ready barrier:
  App import extracts payloads before afterRestore emits completion, although
  ObjImporting remains set until import returns. Visible pending planes load there;
  hidden planes retain the request until first show. No Document ordering patch
  is required. Failed/empty/unsupported conversion clears the old texture and
  preserves calibration/geometry; physical DPI initialization follows successful
  conversion only. A failed nonempty load warns and consumes the request; an
  explicit valid replacement recovers using insertion sizing. Repeated show of a
  materialized plane retains its cache even if the backing file disappears. Empty
  property Paste/undo clears the texture; existing blank-string setValue semantics
  remain unchanged. Included payloads survive deletion of the external original.
  T018 owns broken-archive save/metadata outcomes, and T010 owns final environment
  qualification, including the unsuccessful Qt/IBus lifecycle Memcheck attempts.
- **Receiver lifetime (F003):** start/finish-open subscriptions and scheduled
  callbacks must not outlive TreeWidget. T014 explicitly disconnects both App
  open subscriptions in the destructor alongside the seven existing Gui
  subscriptions, before removing the receiver from the instance registry. The
  unscoped connection member type is unchanged. Owned QTimers and receiver-context
  queued calls cancel with QObject lifetime; the existing delayed focus callback
  also supplies its receiver context. Direct and parent destruction, real App
  document open after deletion, repeated replacement, and queued status work pass
  under Memcheck. This preserves the existing GUI-thread dispatch assumption;
  no concurrent signal/teardown contract or broader scheduler change is added.
  Tree.h is inspected unchanged. T017 qualifies local completion; T007 still owns
  the larger-model/object-effects checkpoint, now locally qualified by T007.
  The new internal-widget test is registered outside Windows because TreeWidget
  lacks DLL export; no public export is introduced for testing. T010 owns final
  platform/native qualification.
- **Numeric and CAD identity (F004):** tokenization and numeric conversion are
  both implementation changes. T015 defines bounded numeric conversion and
  legacy tolerance for signs, whitespace, prefixes, invalid suffixes and range
  limits, now locally qualified with actual restore and sanitizer checks. See
  the numeric policy below. T016 covers semicolon/colon/dollar-hashed forms, decimal child SIDs
  versus hexadecimal mapped SIDs, multiple aliases/SIDs and nested/shared maps.
  Compare semantic save/restore/save and bidirectional name lookup after input
  buffers die; a dependent-feature CAD fixture must retain referenced targets
  after reopening/recomputing. T016 locally qualifies these invariants with 20-ID writer forms,
  aliases and nested/shared-map semantic roundtrips plus the checksum-pinned v0.21 model’s four
  Chamfer.Base edges through two map-bearing save/reopen cycles and three forced recomputes.
  Missing child-SID hashers now warn/omit IDs like the mapped-SID path, instead of dereferencing
  null; malformed/unknown IDs retain warning/omission behavior. The writer and public API remain
  unchanged. CP-005 records these identity invariants; T005 completes the aggregate local
  compatibility gate by binding all four criteria to the unchanged tested composition.
  T010 retains exact-final/platform applicability.
- **Restore completion (F005):** suppression must have a matching completion for
  app open, direct doc.load/doc.restore, import/paste and failure cleanup. T017
  retains broad isRestoring guards against processing and keeps one existing
  owned status QTimer scheduled with one pending flag. Immediate requests become
  delayed during restoration; retry interval is at least 1ms while restoring,
  including a configured zero timeout. Application finish-open requests a flush
  without clearing the flag early. Other restore/import exits resume through the
  timer after the global guard unwinds. The flag clears only when processing
  proceeds past restore/transaction guards, and successful processing stops the
  timer. New restoring document items schedule a pass even without queued objects
  to attach deferred change/touch observers. No App/Gui document signal, flag,
  archive policy, public API, member layout or additional subscription changes
  are needed. T017 qualifies small real-document idle-timer/error paths; T007
  qualifies larger-model, focus/selection and per-object effects locally through
  checksum-pinned 10/514-object documents, with current T014/T017 reruns.
  TreeBehavior uses full Gui services, a MainWindow/active NoneWorkbench and a
  child tree in a panel, matching dock widget ownership. A standalone top-level
  tree is not a valid focus fixture because batching briefly hides it. The
  fixture inputs and generator contract are retained under tests/src/Gui/data.
  T010 retains final platform/mixed-workbench applicability, and T004.3 retains
  the existing benchmark inputs and comparative performance gate.
- **Archive errors (F006):** preserve established compatibility or document an
  approved deliberate change. T018 records empty/nonempty read/write/close
  failures at document level, diagnostics/failure lists, partial-file handling,
  notification state and later-entry continuation. XMLReader catches hook
  exceptions, so hook-only assertions cannot prove archive-level acceptance. T018 now
  qualifies the preserved policy through full Document::restore; see the outcome table
  below. T002 now completes the local aggregate compatibility gate.

### Archive Failure Compatibility Policy

T018 selects preservation of the existing `XMLReader::readFiles` disposition
under the user-authorized completion instruction. This is a delegated local
compatibility decision, not a new upstream policy approval. No production
source, archive format, public API or rollback behavior changes in this task.
The native document-level matrix qualifies the following outcomes on the
recorded Linux debug composition. T002 completes the aggregate included-file gate
with explicit ZIP-entry byte/size, normal application-open and direct hook checks.
T010 retains exact-final/platform applicability.

`Document::restore` catches payload-hook exceptions at the reader boundary,
continues to the next registered entry, and returns without setting RestoreError
or PartialRestore for these included-file failures. A failed **nonempty** entry
emits an error and is added to `XMLReader::FailedFiles`; a failed **empty** entry
emits `Skipped empty embedded file` at log level and is not added. Neither case
is a successful payload completion. The live reader's list is checked from the
second payload hook; it is not assumed available after the reader is destroyed.

Counts below are payload-phase **before/after** notifications. XML property
assignment already supplies its own notifications before dispatch and sets the
property path/basename; it is excluded from these counts. Failure never rolls
back the path or removes partial output. Successful payloads are made read-only;
failed ones do not reach that step. All rows restore the valid second payload
byte-for-byte and read-only, with no second-entry failure.

| Injected operation | Empty first payload | Nonempty first payload | Payload notifications |
| --- | --- | --- | --- |
| Success control | Empty file, read-only; no diagnostic/list entry | All 131089 binary bytes, read-only; no diagnostic/list entry | 1/1 |
| Read error at stream boundary | Empty writable destination; log/absent from failure list | First 65536 bytes retained writable; error/present in failure list | 1/0 |
| Write error before first output write | No write attempted (zero fault hits); successful empty read-only file | Zero bytes retained writable; error/present in failure list | 1/1 empty; 1/0 nonempty |
| Close error returned after actual descriptor close/flush | Empty writable file; log/absent from failure list | All test payload bytes retained writable; error/present in failure list | 1/0 |
| Create/open error (destination is an existing directory) | Directory unchanged; log/absent from failure list | Directory unchanged; error/present in failure list | 0/0 |
| Existing read-only destination | Existing sentinel retained; no diagnostic/list entry | Existing sentinel retained; no diagnostic/list entry | 0/0 |

Retained byte counts are the observed injection points, not guarantees that
arbitrary hardware failures retain those amounts. The close injector reports
failure after releasing the descriptor and flushing known bytes; real failed
close/flush can leave fewer bytes. Read injection uses a throwing streambuf
around the actual ZIP payload reader; write/close injection uses a Linux-only,
thread-local exact-file libc shim linked **only** to App_tests_run. The shim
stays inactive for all other files/threads and is never linked to FreeCADApp,
FreeCADBase or installed application targets. Explicit fault-hit assertions
prevent a nominal failure row from passing without exercising the operation.
The empty write row intentionally proves absence of writes rather than claiming
an impossible zero-byte write failure.

Additional compatibility audit:

- A rejected `PropertyFileIncluded::setValue` for a nonexistent source retains
  the prior value, bytes, read-only state and basename, with no before/after
  notifications, but changes `getOriginalFileName()` to the rejected path.
  That metadata update precedes existence validation. It is intentionally
  recorded as existing nontransactional behavior, not repaired by T018.
- Saving after removal of an empty or nonempty included payload throws
  Base::FileSystemError. The previously saved archive remains byte-identical;
  the failed save leaves a UUID-suffixed temporary archive. The property's path
  is retained. No automatic temporary cleanup or save rollback policy is added.

## Opt-In Restore Benchmark Probe

T004.1 adds developer-only `BUILD_INCLUDED_FILE_PERFORMANCE_PROBE` (default OFF).
Only `PropertyFile.cpp` receives the trace definition/include path; the trace
implementation links into FreeCADApp only when enabled. The native C ABI exposes
numeric thread-local counters without paths or payloads. Normal builds retain
the existing behavior and exports.

The steady-clock interval starts at included-file hook entry and completes after
the copy/read/write/close checks, before permissions and property notifications.
RAII accounts for failure paths; read-only reuse is distinct. No tracing occurs
inside the scalar or buffered copy loop. Start/stop rejects duplicate sessions
and active-hook reset; notification tests prove the successful timer has stopped.
The command worker freezes exact hook/property/byte coverage, independently
checks archive bytes/permissions and model/reference identity outside timers,
and binds the loaded runtime and source commit. Every accepted duration must
match its native nanosecond counter. D006 permits only the two pinned structural
zero controls' payload metric to be not_applicable; other checks remain required.

The shared fault stream supports both `get` and `read` with the same injected
65536-byte boundary, `badbit`, partial bytes and one fault hit. This corrects a
test-harness blind spot exposed by the scalar arm; archive policy is unchanged.

## Diagnostic Intervals And Runtime Resources

T004.2 adds developer-only native wall spans for image load, read/decode,
conversion/Coin copy and owned Coin renderer callbacks. Load is inclusive;
reentrant render spans use a bounded stack and invalidate on overflow. Python
records disjoint operation/setup/swap/completion intervals and a separate glFinish
subset. Residuals are reported only for non-overlapping native spans; they are not
pure scheduling or GPU-upload measurements. All new production-source hooks are
guarded by the existing opt-in BUILD_IMAGE_PERFORMANCE_PROBE; normal builds omit
them. Native source line endings are preserved.

Runtime receipts cover all mapped build files, including Qt RCC resources, while
retaining exact hash equality and foreign-core-library rejection. The retained
BIM/Draft build maps two RCC files absent from the older T020 context; separately
bounded forensics established this precise expectation correction. Future failures
preserve their observed/expected relative-file maps and recomputable differences.

Host telemetry uses an isolated, hash-bound host interpreter with actual pidfd
capability; native workers retain locked Pixi. Source/runtime/package inventories
and initial shader/XDG cache contents are checked before collection; legitimate
cache mutation is recorded afterwards. Observer CPU cost and one-second resolution
limit causal attribution and must be qualified before acceptance. The current
[diagnostic report](t004-p07-diagnostic-results.md) establishes no product budget
or production acceptance. Storage follows the promoted benchmark-storage runbook.

## Conversion Comparison And Isolated Launch

T004.2 constructs bounded historical comparators from a shared retained-lazy
source: P04 varies the recognized direct 32-bit loop only; P05 varies the fallback
while preserving its valid 1/2/4-component storage and current safe extent guards.
Source refs, full-source RCC timestamp equivalence, forced independent compilation,
identical common objects/App/probe and the sole BitmapFactory/Gui delta establish
attribution. No normal production algorithm changes in this measurement slice.

The native opt-in Linux worker times one actual conversion after untimed setup,
then validates every RGBA/orientation pixel (existing one-level quantization
policy), source mutation/destruction ownership and runtime identity. RSS is the
